# 第二轮改动说明（2026-10-20 下午）

这一轮动了 C++ 服务器（`src/`）并重新编译了 `bin/vocab_battle.exe`，不只是前端。
`node --test` 仍 **64 项全过**（其中 2 条断言因为玩法变化被同步更新，见第 5 节）。

## 1. 六项需求

### ① 两人题型不一致 + 文案矛盾

两个问题叠在一起，分开修：

- **玩法**：`src/game.cpp` 的 `startRound()` 原来是「每人从自己选的题型里各自随机」，
  于是同一轮里有人做选择题、有人做拼写，分数却一样。现在改成**每轮抽一个题型，全场统一，取房主的设置**（与难度、与抢答模式一致）。
  新增 `Game::hostTypesUnsafe()`，抢答模式也改用它，避免两处逻辑各写一遍。
- **文案**：前端原来按「题面是单词还是释义」决定提示语，所以「中译英选择」会显示“拼出这个单词”却给出四个选项。
  现在按题型给：英译中选择→“选出这个单词的正确中文释义”、中译英选择→“选出对应的英文单词”、
  英译中→“写出这个单词的中文释义”、中译英→“写出对应的英文单词”、拼写→“拼出这个单词”。
- 加入页的题型提示同步改成「可多选，至少一种 · 开赛时以房主的设置为准」，否则客人会以为自己的选择还有用。

### ② 催促房主太不显眼

原来是一条 2.6 秒的 toast，在最底部。现在：

- 网关把催促的 `INFO` 标成 `kind: 'nudge'`（`room.js onInfo`）；
- 前端改成屏幕顶部居中的金色横幅，8 秒后自动收起，带铃铛图标 + 一行操作提示；
- 同时播一个两声门铃 `public/audio/nudge.wav`（受静音键控制）。

普通提示仍然是 toast，只有催促走横幅。

### ③ 中途退出不再拖住别人

根因不在 C++：网关原来在比赛中给断线玩家 **120 秒**宽限，这期间服务器一直认为他还“在线”，
于是每一轮都要等到他超时才结束——别人答完了还得干等。

现在（`gateway/session.js` + `room.js`）：

- 比赛中 SSE 断开先给 **5 秒**（够刷新页面回来），超时判定为「已退出本局」；
- 判定后立刻对本轮发 `TIMEOUT`，之后**每一轮一开题就直接判超时**，别人答完立刻进下一题（实测 62ms 出结果）；
- **不删会话**：成绩冻结、仍留在实时排行与终局榜单里（实测终局榜单仍含退出者）；
- 名单/提交人数把他排除（`x / N` 的 N 不含退出者），并显示“已退出”标签；
- 5 秒内刷新回来的话自动解除，从下一轮继续（成绩还在）；
- 本局结束后，中途退出的**客人**会被清出房间，避免「再来一局」带着 0 分幽灵（房主不会被清）。

### ④ 错题本（只存本机）

- 新文件 `public/js/mistakes.js`：写 `localStorage` 的 `vb.mistakes`，按「单词 + 题型」去重累加次数，上限 200 条。
- 记入时机：结果页首次渲染且结论是**答错或超时**（被抢先不算，因为那不是不会）。整屏重绘不会重复记。
- 入口放在战绩抽屉里（任何屏幕点「战绩」都能看到）：单词 + 音标 + 词性释义 + 题型 + 错了几次，带「清空」按钮。
- 服务器完全不知道这件事，换设备/清缓存就没了。

### ⑤ 抢答即时判分

- C++ 的 `recordBuzzAnswer()` 本来就已经当场判分并返回结果，只是 `server.cpp` **把返回值丢掉了**。
  现在答完立刻给本人回一条 `BUZZ_OK <得分>` 或 `BUZZ_NO`（`src/protocol.h` 新增两个常量）。
- 网关解析后写进 `question.buzzVerdict`，前端在题卡位置直接显示绿色「抢答成功 +N 分」或红色「答错了 / 本轮已锁定」。
  实测提交到出判分 **64ms**。
- 答对本来就会立刻结束本轮，所以这个改动主要是解决**答错之后只能干等**的问题。

### ⑥ 静音键

- 右下角固定一个 44px 圆钮（🔊 / 🔇），任何屏幕都能按；状态存 `vb.mistakes` 之外的 `vb.mute`。
- 打开时响一声门铃，确认音量正常；静音对答对/答错/催促三种音效都生效。
- 三个音效都在 `public/js/feedback.js` 统一管理。

web\gateway\*.js           ← 必须替换

## 7. 知道但按决定保留的问题（不再改）

1. **抢答的「按铃」界面是死代码**。网关直接拒绝 `buzz` 动作（“题目出现后直接提交答案即可”），服务器也不推「谁在抢」，
   所以那个 200px 的按铃圆永远不出现。当前抢答 = 同时开题、先答对者得分。**保留现状，不影响使用。**
2. **刷新会丢当前轮已输入的内容**（题面会从服务器恢复，输入框是空的）。**按决定不处理。**
3. **抢答没人答对时，`forceBuzzTimeout()` 会把所有人的连击清零**。**按决定不改。**

## 8. 最后一题的对错被结算页盖掉

**原因**：`src/server.cpp` 的 `runRaceGame()` / `runBuzzGame()` 里写的是 `if (r < total) pauseAfterRound();`。
最后一轮发完 `RESULT` + `SCORES` 就直接 `finishGame()` 发 `FINAL`，前端收到终局视图后整屏换页，
结果页只存在了几毫秒——看起来就是“没显示对错直接跳结算”。

**修法**（三处）：

1. C++ 两个循环结束后各补一次 `pauseAfterRound()`：最后一轮也按「轮间停顿」停留。
2. 前端兜底 `app.js`：结果页至少显示 1500ms 才允许切到终局。这样把「轮间停顿」设成 0 的人也不会完全看不到对错。
3. 结果页文案：最后一轮把「下一题 N 秒后开始」换成「比赛结束 · N 秒后公布最终结果」（`screens.js`）。

**验证**：脚本实测 pause=3 时结果页停留 **3033ms**，之后才进终局；64 项测试仍全过。

## 9. 房间公屏（实时群聊）

**传输**：

- 新增 `POST /api/chat  { sid, text }`；
- 广播走 SSE 的 `chat` 事件，重连/刷新时先补一份 `chat-history`（最近 60 条）；
- 消息只在网关内存里，服务器重启即清空，不落盘、不进 csv。

**限制**：

| 项 | 值 | 位置 |
|---|---|---|
| 长度 | 1–120 字（去控制字符、折叠空白） | `room.js chat()` |
| 频率 | 每人 1.2 秒最多一条 | 同上 |
| 保留 | 最近 60 条 | 同上 |
| 答题中 | **禁止发送**，输入框变灰并提示「答题进行中，暂不能发言」 | 同上（`session.stage === 'quiz'`） |

> 答题阶段禁发是有意的：题型已经统一、全场同一道题，答题中开聊等于给了泄题通道。
> 想放开就把 `room.js` 里 `if (session.stage === 'quiz') throw ...` 那一行删掉，前端 `app.js` 里
> `chat.setEnabled(state.screen !== 'quiz')` 改成 `true`，两处都改就行。

**界面**：右下角 💬 按钮（在静音键上方，44px 圆钮），有关闭时的新消息红点；
面板含昵称（用与头像同一个色相着色）、房主标记、时间、气泡；自己的消息用淡主色底。
移动端面板改成左右各 14px 的通栏。

**顺手修的**：答题页的 A–D / 1–4 快捷键现在会忽略来自 `input`/`textarea` 的按键——
否则在公屏里打字时，字母键会误触发选项选中，回车会误提交答案。
