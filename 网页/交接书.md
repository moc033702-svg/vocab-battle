## 1. 它是什么

一个课堂用的英语词汇多人对战网页。老师开一局，学生用手机或电脑打开同一个地址加入，同题竞速答题，
实时出分、实时排行、实时公屏。一套代码，两种用法：

- **网页版**：Node 网关 + 浏览器（本文档的主角）
- **命令行版**：同一个 C++ 程序自带的客户端（`src/client.cpp`），网页版用不到

**技术栈**：零依赖。原生 ES 模块 + 手写 CSS，没有框架、没有构建步骤、没有 npm 依赖、没有网络字体、没有 CDN。
唯一的 npm 依赖是 `node --test` 需要的无，`package.json` 里只有脚本。

## 2. 三层结构与数据流

```
浏览器 (public/)  ←── SSE (event: view / notice / chat) ──┐
      │                                                    │
      └── POST /api/join | /api/act | /api/chat | GET /api/stats
                          │                                │
                    gateway/ (Node)  ─── TCP 行协议 ───► bin/vocab_battle.exe (C++)
```

| 层 | 目录 | 职责 | 谁改得动 |
|---|---|---|---|
| 界面 | `public/` | 渲染、输入、动画、本地存储（错题本、静音、会话） | 前端/设计 |
| 网关 | `gateway/` | HTTP 接口、SSE 推送、玩家会话、公屏、排行聚合 | 需要懂 Node |
| 游戏核心 | `src/` | 出题、判分、计分、赛程、存档（C++，需重新编译） | 需要懂 C++ |

**关键约定**：C++ 只对每个玩家发他自己的 `RESULT`，不广播；名单、分数、排行都是网关**按昵称**自己攒的。
所以换昵称会丢成绩，重连靠「同名 + 未过期」识别。

## 3. 五条铁律（违反一定出问题）

1. **不要删** `public/css/style.css` 里的
   `#app[data-same="1"] .screen { animation: none; }`
   每次收到新视图都会整屏重建 DOM，删了之后「有人提交 → 全场闪一下」。
2. **整屏重建**：`app.js` 的 `render()` 用 `replaceChildren` 重建整个屏幕。所以
   - 只在 DOM 里存的状态（展开态、滚动位置）会丢；要保留就放进 `ui` 对象；
   - 入场动画只能挂在 `#app[data-same="0"]` 下（换屏/换轮那一次才是 0），
     并且 `animation-fill-mode` 用 `backwards` 而不是 `both`——用 `both` 会让动画结束态压住 `:hover` 的 `transform`。
3. **所有文本走 `h()`**（内部是 `textContent`）。不要出现 `innerHTML` / `insertAdjacentHTML`，词库和玩家昵称都会进来。
4. **不要改钩子名**（第 4 节）。要加样式就加新类名，别动老的。
5. **不要加依赖**：不加框架、不加 CDN、不引外部字体/图标库、不加构建步骤。图标只能是内联 SVG 或 CSS 画的形状。

## 5. 第三轮（视觉润色）改了什么

### 5.1 新文件

| 文件 | 作用 |
|---|---|
| `public/js/ui/icons.js` | 线性图标集（`icon('check')` 返回 `<svg>`），替换了全部 emoji |
| `第三轮美化方案.md` | 本轮的施工单（含色值对照表），保留作依据 |

### 5.2 结构性改动

| 位置 | 改动 |
|---|---|
| `index.html` | 加了 data URI favicon（原来每次打开都报 `favicon.ico 404`）、`interactive-widget=resizes-content`（键盘不遮输入框）；去掉 `#app` 上的 `aria-live`（整屏重建会让读屏重读整页） |
| `:root` | 新增 `--surface-3 / --accent-strong / --accent-text / --gold-text / --ok-text / --bad-text / --bad-ink / --warn-ink / --shadow-1 / --hairline / --font-latin / --font-ipa / --font-mono / --ease-out / --ease-spring`；`--text-3` 由 `#8a8272` 加深到 `#756d5d` |
| 两份暗色块 | 同步重写（`@media (prefers-color-scheme: dark)` 与 `:root[data-theme="dark"]`，**必须一字不差**） |
| `:focus-visible` | 删掉 `border-radius`——它会把胶囊按钮按成 6px 方角 |
| `app.js` `render()` | 第一行加 `document.body.dataset.screen = state.screen`，供 CSS 在手机上让浮动按钮避开吸底按钮 |
| `screens.js` | 拼写提示改成 `hintLetters()`（`a…`）；「已提交」页加进度条；排行榜行加 `is-me`；终局名次改成**并列**（同分同名次，下一个跳号），标题按并列人数显示「擂台冠军 / 并列冠军」 |
| 浮动按钮 | 手机上横排（右 14 / 右 66），加入页隐藏静音键，答题页隐藏公屏键 |

### 5.3 全部新样式的位置

从 `style.css` 里 `/* 第三轮润色（追加区块… */` 这一行开始到文件末尾，是一个**独立区块**。
出问题整块删掉就能回到第二轮的样子（`:root` 与 `:focus-visible` 的 A 类改动除外，那两处是原地改的）。

### 5.4 刻意保留的问题

1. **抢答的「按铃」界面**（`buzz-btn`）是死代码：网关直接拒绝 `buzz` 动作，服务器也不推「谁在抢」。
   现在的抢答 = 同时开题、先答对者得分。留着只是因为删它要动 `screens.js` 的四个分支。
2. **客人选的难度/题型对开赛无效**（题型和难度都取房主）。加入页的控件保留，是因为加入前无法知道会不会当房主。
3. **答对率**：服务器只累计「答对题数」和「场次」，算不出百分比，所以抽屉里显示的是「答对题数」。
4. **投影放大**：本轮按产品决定**不做**。所以 ≥1440 宽的屏幕上界面就是正常尺寸，不会自动放大。
5. **刷新会丢当前轮已输入的内容**（题面和倒计时会恢复，输入框是空的）。

## 6. 怎么跑、怎么验证、怎么回滚

```powershell
cd "<项目目录>\网页"

# 只调界面（不需要游戏服务器）
#   浏览器打开 http://127.0.0.1:3000/?mock=1      ← 假后端，三个人（你 + 两个机器人）
#                  http://127.0.0.1:3000/?mock=1&role=guest
node gateway\server.js

# 完整链路（需要 bin\vocab_battle.exe 和 data\words.csv）
node --test tests/protocol.test.js tests/integration.test.js tests/rules.test.js tests/patches.test.js tests/bugs.test.js
# 期望：64 项全过
```

**改完必须过一遍的清单**

1. `node --check` 每个改过的 JS（`h()` 嵌套少一个括号会让整页空白，页面 Console 还经常读不到）；
2. 64 项测试；
3. `?mock=1` 走：加入 → 大厅 → 三题（选择/拼写/超时）→ 结果 → 终局 → 再来一局；
4. 1280 与 390 两种宽度、亮/暗两套主题、Console 0 报错、无横向滚动条；
5. 答题时故意让机器人先提交，确认题卡不闪、已选项不重播动画。

**双人联调的小技巧**：同一个浏览器里 `127.0.0.1:3000` 和 `localhost:3000` 是两个 origin，
localStorage 不共享，所以开两个标签页就能分别当房主和客人，不用两台设备。

**回滚**
- 只回滚视觉：删掉 `style.css` 里第三轮区块；
- 回滚整轮：`.backup-public-20261020/`（第一轮前的 public）、`.backup-bin-20261020/`（旧 exe）。
